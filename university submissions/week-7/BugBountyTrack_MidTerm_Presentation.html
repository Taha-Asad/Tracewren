Core Business Logic & Calculation Engine

Feature 1: Deterministic CVSS v3.1 Calculation Engine

Pure TypeScript implementation of the FIRST.org Common Vulnerability Scoring System v3.1 specification with zero third-party runtime dependencies.

FIRST.org Mathematical Formulation
Calculates Base Metric Group across 8 independent security dimensions:

1. Impact Sub-Score (ISS):
ISS = 1 - [(1 - ConfImpact) × (1 - IntegImpact) × (1 - AvailImpact)]

2. Scope-Dependent Impact:
Scope Unchanged: Impact = 6.42 × ISS
Scope Changed: Impact = 7.52 × (ISS - 0.029) - 3.25 × (ISS - 0.02)^15

3. Exploitability:
8.22 × AttackVector × AttackComplexity × PrivilegesRequired × UserInteraction

4. Deterministic Roundup9:
Pure mathematical ceiling to 1 decimal place eliminating IEEE 754 floating-point drift.

Scoped Multi-Tenant Communications

Feature 2: Scoped Program & Report Triage Communications

Eliminated generic single-room chat and simulated bots in favor of true multi-tenant, program-scoped collaborative triage with segregated deliberation channels.

The Domain UX Problem
In enterprise bug bounty platforms, generic global chat fails completely:

Program Heterogeneity: Each program (e.g. Core Banking API, Cloud Infrastructure, Mobile Authenticator) has different assigned engineers and security policies.

Vulnerability Secrecy: Discussions must be bound strictly to specific vulnerability findings to prevent cross-finding information leakage.
DOMAIN PROBLEM SOLVED
Two-Level Scoping Mechanism
Level 1: Target Program Scope
Filter discussions by program domain. Automatically resolves and displays the authorized member roster for that specific program.

Level 2: Vulnerability Finding Thread
Select specific finding thread (e.g. BBT-0241). Isolates communication strictly to the finding context.

Administrative Freeze:
Organization Owners can lock threads upon resolution to preserve legal audit custody.
HIERARCHICAL ISOLATION
Dual-Lane Channel Isolation
Class B (Researcher Coordination):
External researcher communicates directly with defenders to clarify reproduction steps, payloads, and validation status.

Class C (Internal Deliberation):
Encrypted internal engineering channel. Defenders discuss root-cause code fixes, bounty approvals, and patch schedules.

Zero Leakage: Class C records are completely stripped from external researcher responses.

Viva Voce & Defense Preparation

Supervisor Defense FAQ: Technical Oral Examination

Anticipated questions and authoritative technical answers prepared for the faculty evaluation panel.

Q1: How does your CVSS calculation differ from third-party calculators?
Our CVSS 3.1 engine is implemented directly from FIRST.org mathematical specifications with zero runtime dependencies. It computes floating-point impact and exploitability sub-scores, executes exact Roundup9 arithmetic, and automatically binds the derived score to organization-specific SLA countdowns and bounty award brackets.
Q2: How do you prevent internal defense notes from leaking to external hackers?
Through architectural dual-lane segregation at both the database and API serialization levels. Class B messages (coordination) are accessible to both parties, while Class C messages (internal engineering deliberation) are completely stripped from external API responses by NestJS response interceptors.
Q3: How is multi-program team isolation enforced when multiple programs coexist?
Every program is bound to an organization ID and maintains its own authorized members roster. Discussions and report queues are scoped using foreign keys (programSlug, reportId). Even within the same organization, different defender teams can be assigned to different programs without overlap.
